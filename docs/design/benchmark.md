# 本机性能与资源验收

日期：2026-09-25。机器为 NVIDIA GB10 / aarch64，约 121GiB 系统内存；网关使用 GCC 13、C++23、release 构建、8 个 IO 线程。模型为本机 Qwen3.6；网络全部为 loopback 明文 HTTP。

## 方法与结果

| 场景 | 配置 | 实测 |
| --- | --- | --- |
| healthz | wrk 4 线程 / 256 连接 / 30 秒 | **550341.09 req/s，p99 2.07ms**；16527677 请求 |
| 缓存命中 | 同上；真实 Qwen 响应预热，temperature=0 固定 POST | **347312.35 req/s，p99 3.19ms**；10439953 请求 |
| 直连 vs 网关 TTFB | 各 20 次，交替发出；流式，禁用思考，max_tokens=32；网关 bypass 缓存 | 中位数 **4.1615ms / 45.7400ms**；差值 **41.5785ms** |
| 1000 并发慢速流 | fault_upstream rate=2,tokens=100 | **1000/1000 完成，0 错误**；活动流峰值 1000；RSS 16.07→28.88 MiB |
| 100 慢读者 | fault rate=1000,tokens=10000；接收缓冲 4096B、asyncio limit=1024；前 10 秒不读取，再以约 200B/s 读 5 秒后取消 | **100/100 建立，100 次背压暂停**；RSS 10.34→22.25 MiB；活动流峰值 100 |

1000 流场景采样时长 79.32s，网关累计 CPU 4.20s；慢读者场景 15.03s、CPU 3.54s。CPU 数值为 /proc 的进程 CPU 秒数，未换算为单核百分比。

## 解释与边界

- wrk 两项输出无 socket 错误或非 2xx 提示。测试关闭用户/模型限流，关闭数据库账本，访问日志保持异步轮转；不能把这些吞吐数当启用 PG/Redis 和真实推理后的吞吐能力。
- TTFB 使用 curl 的 time_starttransfer：直连上游可先发 HTTP 头，网关等待可转发事件后提交响应。约 41.6ms 的差值包含提交语义和上游等待，不是隔离测出的网关 CPU 开销，也不宣称已达到低于某个延迟目标。
- 慢读者配置 high_water=65536，100×水位为 6.25MiB；RSS 还包含基线、每连接读批次、解析缓冲和分配器，不等于这一乘积。实测增量 11.91MiB，约落在 100×(64KiB 水位+64KiB 读取批次) 范围；这是固定场景的观测，未声称任意负载下的严格进程 RSS 硬上限。
- 首轮慢读者使用大客户端缓冲，不能证明真正背压；其记录保留但不作为背压结论。本表使用收紧接收缓冲后单独重跑的结果。
- 慢读者只观测 15 秒并主动取消，未等待数分钟的全文下载；故障服务仅用于并发/慢读行为，功能正确性另由真实模型和 DAgent 验证。
- 测量基于 G14 release 代码及当时配置；随后 G15 的配额/进度计量修复在未启用 PG/Redis 的吞吐路径之外，未重复整轮压测。
