# API Key 管理页面设计

状态：**真实验收通过**。日期：2026-09-25。

本文保留设计合同；实现调整和实际验证边界见 [实现摘要](../docs/design/management.md) 与 [验收记录](../docs/acceptance/api-key-management.md)。

## 1. 目标与范围

提供一个本机打开的管理页面，创建用于调用网关的 API Key，查看每个密钥的 Token 消耗，并禁用不再使用的密钥。无管理员账号、登录、角色或用户体系。

本期交付：

- 创建密钥：填写名称，生成后一次性展示完整密钥并支持复制。
- 密钥列表：名称、脱敏密钥、启用状态、今日和累计实际消耗。
- 用量详情：按日期查看输入、输出、上游缓存 Token、实际消耗和请求明细。
- 禁用密钥：拒绝后续新请求，保留历史消耗；本期禁用不可恢复。
- 重启后保留密钥及禁用状态，创建和禁用无需重启网关。

本期不包含：管理员登录、多租户、用户自助注册、充值结算、模型管理、额度编辑、密钥改名/轮换/重新启用、硬删除、报表导出和公网部署。已有静态配置密钥继续可用，但不纳入本页管理或自动迁移。

默认单网关实例管理一套动态密钥；不承诺多实例间即时传播禁用状态。既有推理与账本能力保持兼容。

## 2. 用户故事

1. 作为网关使用者，我希望输入名称创建密钥，以便给不同调用方分别使用。
2. 作为网关使用者，我希望创建后复制完整密钥，以便配置到自己的客户端。
3. 作为网关使用者，我希望看到所有已创建密钥及其状态，以便识别当前可用的密钥。
4. 作为网关使用者，我希望看到每个密钥今日和累计消耗，以便判断使用情况。
5. 作为网关使用者，我希望选择日期范围查看某个密钥的消耗，以便了解一段时间内的使用情况。
6. 作为网关使用者，我希望查看请求的模型、结果和 Token 明细，以便定位消耗来源。
7. 作为网关使用者，我希望禁用密钥后仍能查历史，以便停止使用而不丢失记录。
8. 作为网关使用者，我希望重启后密钥和记录仍在，以便长期使用。
9. 作为网关使用者，我希望零消耗、尚未入账、上游未完整报告和查询失败有明确区别，以便正确理解数字。
10. 作为网关使用者，我希望创建失败或结果丢失时有明确提示，以便处理未保存的密钥而不误以为创建成功。

## 4. 页面与交互

入口 `/manage/`，同一个页面内用侧边详情面板查看用量。中文界面，轻量 HTML/CSS/JavaScript，不引入前端框架、Node 运行服务或外部 CDN。静态资源随网关构建打包，页面加载不依赖互联网。

```text
API 密钥                                      [创建密钥]

名称          密钥          状态       今日消耗    累计消耗    操作
开发客户端    gwk_…7f2a     启用       12,300      81,500     查看 / 禁用
旧客户端      gwk_…92bc     已禁用      0          16,700     查看

点击查看 → 用量详情
开发客户端                                  [日期起止] [查询]
实际消耗       输入 Token       输出 Token       上游缓存 Token
按日用量表
请求明细：时间 / 模型 / 结果 / 输入 / 输出 / 实际消耗 / 上报状态
```

### 4.1 创建

- 名称去除首尾空白后为 1–64 个 Unicode 字符；拒绝控制字符。允许同名，列表使用脱敏密钥和创建时间区分。
- 创建按钮提交期间禁用；成功后弹窗展示完整密钥和复制按钮，说明“仅此次显示，请保存”。
- 页面不把完整密钥存到 localStorage、sessionStorage、URL 或分析事件；弹窗关闭即清除页面引用。关闭前提醒用户保存，不强制要求剪贴板操作成功。
- 复制失败允许手动选取复制；页面不记录明文。刷新页面不会恢复完整密钥。
- 数据库提交后响应丢失：刷新列表确认新条目，禁用该条目后重新创建；不自动重试 POST，也不设计可恢复明文的后门。

### 4.2 列表和详情

- 列表默认按创建时间倒序，包含已禁用密钥；每页 50 项，最大 100 项。
- 每行显示今日、累计实际消耗；详情默认今天，可选近 7 天、近 30 天或自定义起止日期。
- 详情先提供按日表和分页明细，不引入图表依赖。今日边界遵循网关已配置的计费时区。
- 提供刷新按钮；页面可见时每 10 秒刷新当前列表或当前详情，切到后台停止轮询；请求不重叠，切换密钥/日期后忽略旧响应。
- 零记录显示“暂无消耗”；查询失败显示错误和重试入口，不能显示为 0；保留旧数据显示时标注更新时间和刷新失败。
- 提示“已入账用量，进行中的请求结束后更新”；禁用密钥后，在途请求完成仍可能增加历史用量。

### 4.3 禁用

- 点击禁用时确认名称和脱敏密钥；操作成功后状态变为已禁用，隐藏禁用按钮。
- 禁用不可恢复，不删除账本；需要继续调用时创建新密钥。
- 重复禁用返回当前状态，属于幂等操作。

## 5. 访问边界

无登录和管理员凭证；访问能力建立在本机连接上。

- `/manage/`、其资源和 `/api/manage/*` 只接受实际 TCP 对端为 loopback 的连接；忽略 X-Forwarded-For 等转发头。
- 使用现有 HTTP 监听端口，校验 Host 为 localhost、127.0.0.1 或回环 IPv6，端口必须匹配本次监听端口；IPv4-mapped IPv6 统一规范化判断。
- 新管理路由的本机限制不可被 `admin.listen_local_only=false` 关闭。所有管理请求必须经过同一个入口检查。
- 写请求要求 JSON、同源 Origin 和固定自定义头 `X-Gateway-Management: 1`；不启用 CORS。该头不是密码，也不是登录机制。
- GET 在携带 Origin 时也校验同源；返回禁止被其他站点嵌入的策略。页面脚本和样式仅同源加载，用户名称按纯文本渲染。
- 管理响应使用 `Cache-Control: no-store`，完整密钥不进入请求/响应日志和异常文本。

本机进程均可使用管理能力，这是无登录方案的明确边界；不将管理路径转发到公网。访问控制仅影响管理端，现有推理 API 的密钥鉴权保持有效。

## 6. 密钥、身份与持久化

### 6.1 生成与保存

- 密钥使用 `gwk_` 前缀加 32 字节操作系统安全随机数的十六进制编码。必须使用 `getrandom` 或等效安全随机源，不能复用当前基于 mt19937 的 `randomHex`。
- 数据库只保存完整密钥的 SHA-256 摘要、末 4 位和公开 ID；对高熵随机密钥按摘要建立唯一索引。完整密钥只存在于创建流程内存及一次成功响应中。
- 输入鉴权时计算摘要并查注册表；接口、日志和账本仅携带 ID/脱敏文本，不暴露摘要。
- 新建 `api_keys` 表：

| 字段 | 约束与含义 |
| --- | --- |
| `id` | 不可变 UUID，主键，不包含秘密 |
| `name` | 页面展示名，不参与账本归集 |
| `token_hash` | SHA-256 摘要，唯一、非空 |
| `token_last4` | 脱敏展示用末 4 位 |
| `status` | enabled / disabled |
| `created_at` | 创建时刻，timestamptz |
| `disabled_at` | 禁用时刻；启用时为空 |

原有部署密码、上游密钥继续遵守 AGENTS.md 第 6 条，仅从环境变量或 `deploy/.env` 输入。网页生成的调用密钥由网关内部生成，仅持久化摘要，不将明文写回配置、环境文件、文档或验收材料。

### 6.2 与旧身份兼容

- 动态密钥的内部记账身份固定为 `managed:<id>`。复用现有 `key_name` 列存储该身份，`UserConfig::name` 的旧记账含义在主体快照中保持稳定；页面展示名独立保存。
- 保留 `managed:` 为内部命名空间。启用管理功能时，若静态用户 name 或历史账本已有这一前缀且不能对应动态密钥，启动报明确冲突，不静默关联。
- 静态密钥的鉴权和旧账本查询不变，不按显示名称迁移旧数据。同名动态密钥始终独立统计。
- 鉴权统一产出主体快照：包含稳定记账身份、来源、现有限流/配额配置。动态密钥不单独配置 RPM/TPM/额度，仍受模型级及网关现有全局限制。
- 动态密钥同样支持 Bearer 和 x-api-key；所有需鉴权的推理、models、count_tokens、自助 usage 入口使用一致的解析链路。
- 动态禁用命中后直接拒绝，不允许退回静态配置绕过状态；创建时对静态密钥摘要做冲突检查，启动加载时发现静态/动态摘要冲突则拒绝开启该功能。

### 6.3 发布、并发与生命周期

- 新增 `KeyRegistry`：保存不可变注册表快照，IO 线程通过原子共享指针读取，鉴权热路径不访问数据库。
- 新增 `KeyStore`：由 ledger loop 持有专用 PG 控制连接，处理创建/禁用；使用有界队列串行执行，避免异步事务互相穿插或阻塞账本写连接。
- 新增 `ManagementApi`：处理参数、访问边界和响应；用量查询复用现有 ledger loop 与账本读通道，查询有超时、分页和范围限制。
- 创建顺序：安全生成 → 校验/预构造新快照 → PG 提交 → 原子发布快照 → 原 IO loop 返回 201。201 后开始鉴权的新请求可以使用该密钥。
- 禁用顺序：预构造新快照 → PG 提交 → 原子发布 disabled 状态 → 返回 200。以读取注册表快照完成鉴权为边界，之后的新请求必须返回 401；已通过鉴权的请求允许完成并正常入账。
- 请求和异步 usage 回调持有主体快照的共享所有权；更新注册表不释放在途请求正在使用的主体。禁止在回调里捕获临时 UserConfig 引用。
- 客户端断开不撤销已提交事务；提交结果不确定时暂停管理写入和动态密钥新准入，重新读取 PG 后发布一致快照，不能沿用可能已经失效的状态。
- PG 失败时创建/禁用不能返回成功。启动需在迁移、注册表加载完成后开放动态密钥鉴权；失败返回服务不可用，不回退到空列表。
- 退出时先关闭管理写入准入，等待在途控制事务，沿用 IO/ledger 清理屏障；回调用连接弱引用，服务对象存活至回调清理结束。

配置增加 `management.enabled`，缺省 false。启用时必须配置 PostgreSQL，并执行新表迁移。Redis 仅用于既有配额功能，本页统计不依赖 Redis。未启用时新路由返回 404，不改变原有网关部署要求。

## 7. Token 口径

页面主指标采用现有 `billable_tokens`，文案为“实际消耗 Token”；它是各次上游尝试已知 consumed 的总和，不是货币费用。

| 页面字段 | 数据来源与解释 |
| --- | --- |
| 今日消耗 | 计费时区今日 `usage_daily.billable_tokens` 合计 |
| 累计消耗 | 该稳定身份全部 `usage_daily.billable_tokens` 合计 |
| 日期范围实际消耗 | 日期闭区间内的相同合计 |
| 输入 / 输出 Token | 原账本 input_tokens / output_tokens；沿用原记录口径 |
| 上游缓存 Token | cached_tokens，是输入中的缓存部分，不能再与输入相加 |
| 未完整上报请求 | unreported_requests；展示“消耗可能不完整” |

网关响应缓存命中时，返回给客户端的 usage 可以保留原响应 Token，但本次实际消耗为 0；这是网关缓存与上游 prompt 缓存的区别。重试/降级可能让实际消耗高于最终响应的输入加输出，页面应提供简短说明。

明细中未知字段显示“未上报”，不能把 null 转成 0。汇总是已知消耗下界，有不完整请求时必须显式标注。详情显示账本中的原始 input/output/cache 计数，不在浏览器重算 consumed。

账本异步批量提交，所以查询表示已提交的数据，不承诺实时逐 Token 刷新。列表请求计数沿用已入账请求数，不把未入账的 401 等视作模型请求。

累计指标复用日汇总表，不从有界最近请求缓存或临时访问日志计算。未来明细清理不得删除累计依赖的日汇总；如引入汇总保留策略，必须同步调整“累计”定义。

## 8. HTTP API 合同

路径统一使用 `/api/manage`；不要求推理 API Key。公共响应遵守第 5 节本机访问限制。

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| `GET /api/manage/keys` | limit、cursor | items、next_cursor、as_of、billing_timezone |
| `POST /api/manage/keys` | JSON name | 201：key 元数据、secret，仅此处返回明文 |
| `POST /api/manage/keys/{id}/disable` | 空 JSON 对象 | 200：更新后的 key 元数据 |
| `GET /api/manage/keys/{id}/usage` | start、end，均为 YYYY-MM-DD | key、start、end、total、days、as_of、billing_timezone |
| `GET /api/manage/keys/{id}/requests` | start、end、limit、cursor | requests、next_cursor、as_of |

- `key` 元数据包含 id、name、masked_key、status、created_at、disabled_at，不包含摘要。
- 列表每项附 today_tokens、total_tokens、today_unreported_requests、total_unreported_requests；批量关联当前页身份并查询，不逐行发起 SQL。
- usage 的 total/days 包含 requests、input_tokens、cached_tokens、output_tokens、billable_tokens、unreported_requests、truncated_requests，按天汇总全部模型。
- 明细包含 ledger_id、finished_at、model、outcome、http_status、input_tokens、cached_tokens、output_tokens、billable_tokens、usage_complete；不返回 prompts 或响应正文。
- usage/requests 缺省均查今天，日期为计费日闭区间；范围最长 366 天，start 不得晚于 end。列表累计不受该范围限制。
- requests 按 `(finished_at, ledger_id)` 倒序，cursor 包含完整二元位置并绑定 key_id 和筛选日期；相同时刻不能漏记录。列表按 `(created_at, id)` 游标分页。limit 缺省 50，上限 100。
- 所有查询参数严格解析并检查重复参数、日期和游标合法性；使用参数化 SQL。补充账本 `(key_name, finished_at, ledger_id)` 索引，日期过滤使用现有 billing_day。
- 同一响应内使用一次查询或一致性读事务获取列表及汇总，避免一页内读到不同提交状态。`as_of` 表示查询时刻，不代表所有进行中的请求已经入账。
- 计数字段均以十进制字符串传输，避免 JavaScript Number 超过 2^53 时失真；浏览器以 BigInt 格式化。该约定只作用于新管理 API，不改变旧 usage 协议。
- 错误体统一 `{error: {code, message}}`，不包含数据库连接串、SQL 内部错误或密钥。
- 状态码：400 参数错误；403 非本机或来源检查失败；404 功能关闭/ID 不存在；405 方法错误；413 请求体过大；503 数据库/初始化/控制队列不可用；500 内部失败。已禁用密钥调用推理 API 返回原协议格式的 401。
- 创建/禁用请求体上限 4 KiB。创建无自动重试；禁用可安全重试。所有更新只使用 POST，不通过 GET 修改状态。

旧 `/admin/usage` 的 key 参数继续表示内部记账身份，旧接口保持兼容；网页仅通过新 API 使用公开 UUID，不依赖旧接口字段名或其潜在解析缺陷。

## 9. 代码与资源组织

- `.hpp` 放 `src/public/gateway/` 或 `src/public/store/`，对应 `.cpp` 放 `src/private/` 的同模块目录。
- 页面源文件放 `web/management/`；构建时打包为构建目录内的资源数据，由 gateway 模块资源服务返回固定路径，避免任意文件读取。
- 注册表/鉴权不依赖页面；页面只依赖管理 API；用量管理复用 ledger，不另建计量实现。
- 新增 DB migration 通过现有迁移机制执行；不修改已执行的旧版本迁移。
- `GatewayContext` 挂注册表及管理服务依赖；main 负责装配与退出顺序。静态配置对象仍保持不可变。
- 同步更新 docs 的运行说明、账本身份说明和线程所有权说明；不将待实现内容写成已交付行为。

## 10. 验收条件

遵循 [构建与验证](../docs/validation.md)，实现任务见 [G16–G20](implementation-tasks.md)。

1. 浏览器无登录直接进入本机页面；远端 TCP 来源、非法 Host、跨站写请求不能管理密钥。
2. 页面创建密钥后立即可通过真实模型完成 OpenAI/Anthropic 两种入口请求；数据库和日志中无密钥原文。
3. 两个同名密钥分别调用真实模型，页面、PG、已有 usage/访问日志按稳定身份核对，无相互串账。
4. 今日/累计/日期范围包含正确的计费日边界；缓存 MISS/HIT 的实际消耗分别与账本一致，缓存 Token 不重复相加。
5. 重试/取消等不完整记录保留原语义；使用真实调用优先，必要时使用唯一允许的 fault_upstream 注入稳定故障。
6. 禁用返回成功后新请求被拒绝；并发在途请求可完成，正常入原密钥账本；重复禁用成功且不改变原禁用时间。
7. 重启测试网关后仍能使用未禁用密钥、拒绝禁用密钥并查到原用量，不重启模型服务。
8. PG 不可用、创建响应丢失、初始化失败和提交不确定时，页面与接口不伪报成功或零用量；恢复后状态与 PG 一致。
9. 翻页遇到相同时间戳不丢记录；大整数、空列表、长名称、非法输入、隐藏页轮询及旧响应覆盖均按设计处理。
10. 现有静态密钥、两种推理协议、缓存和 usage 入口回归通过；未启用管理功能时无新的 PG 依赖。

真实验收脚本、截图和脱敏记录放 `temp/G16/` 至 `temp/G20/`；创建结果里的 secret 只驻留调用进程内存，不落盘、不截图。单测限于纯逻辑，数据库和浏览器行为使用真实环境验收，不新增辅助测试服务。
